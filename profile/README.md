<p>"一挂一片"是团队最怕看到的场面：早上打开后台，五六个号同时提示异常，逐个申诉又找不到共同点。多数时候共同点是有的，只是藏在出口那一层。这篇按故障树的方式拆：顶事件是批量账号同时异常，往下分三条主要分支——地址段被整段识别、多个号共用同一条出口、登录地反复跳变。每条分支给出判定信号、排查命令和止损动作，最后串成一套二十分钟内能跑完的排查顺序。</p>

<h2>一、先定顶事件：批量异常的共同点在哪一层</h2>
<p>把"一挂一片"当顶事件，往下找必要条件。账号本身几乎不会同时出问题，密码不会集体失效，订阅也不会同一天到期，所以共同点只可能落在网络层或设备层。</p>
<h3>先排掉非网络因素</h3>
<p>看后台告警文案：提示"异常活动"通常指向行为与环境，提示"无法登录"多半是密码或邮箱问题。再看时间分布，同一分钟内集中异常，基本可以锁定同一条出口；相隔几小时陆续异常，更像逐号触发，要往设备指纹或使用行为上查。</p>
<h3>把"片"的边界画出来</h3>
<p>导出这批账号最近 7 天的登录 IP，按 /24 段聚合。如果异常账号绝大多数落在同一个或相邻两个 /24 里，就是段级问题；如果分散在多个不相关段，则不是出口本身，而是别的共同条件。</p>

<h2>二、第一条分支：出口地址段被整段识别</h2>
<img src="/tp.png" alt="Claude账号批量异常时按出口地址段逐层排查的分支示意">
<p>机房段的问题不在于"被看见"，而在于一整段 IP 的可疑评分是共享的。同一段里只要有足够多的人在做同样的事，整段的评分就会被拉低，落在这段里的号就成了陪绑。</p>
<h3>怎么确认是段级</h3>
<p>用 <code>curl -s https://ipinfo.io/1.2.3.4/json</code> 逐个看 org 与 asn 字段，如果全部指向同一家云厂商或 IDC，且 asn 相同，段级判断成立。再用 <code>whois -h whois.cymru.com " -v 1.2.3.4"</code> 交叉验证 ASN 归属，两处结果一致就不用再怀疑。</p>
<p><strong>判定阈值：</strong>同一 /24 段内异常账号达到 3 个及以上，按段级问题处理；同一 ASN 下异常账号超过账号总数的六成，说明整个 ASN 都不适合继续承载这批号。阈值不必精确，目的是让"要不要整段撤"这个决定有个明确触发点。</p>
<h3>处置动作</h3>
<p>整段撤，不要逐号换。逐号换的结果是新号又落回同一段，问题循环。换到 ISP 归属的原生家宽出口，撤完先跑 48 小时观察，再决定是否恢复批量使用。</p>

<h2>三、第二条分支：多个号共用一条出口</h2>
<p>这条分支最隐蔽，因为出口本身可能是干净的住宅地址，问题出在承载量上。</p>
<h3>怎么确认共用</h3>
<p>查代理网关的连接日志，按源账号聚合出口 IP。一天内同一条出口出现两个以上账号，且登录时段有重叠，基本可判共用。开源面板如 3x-ui、v2board 都能直接看到在线连接列表，商业代理则在控制台的会话明细里看。</p>
<h3>共用为什么会连坐</h3>
<p>同一条出口上，账号之间的行为差异会变成"同一用户的多重人格"：一个在传大文件，一个在快速提问，一个在深夜活跃。平台看到的是同一地址上互不相关的行为模式，这种不一致本身就是可疑信号。</p>
<h3>处置动作</h3>
<p>拆成一号一出口。拆的时候注意顺序：先拆活跃度最高的号，观察 24 小时，再拆下一个。一次性全部迁移会造成大范围登录地变化，反而制造新的波动。</p>

<h2>四、第三条分支：登录地在相邻地区反复跳</h2>
<p>有人以为只要不出境就没事，实际同一城市内跨运营商、跨城域网跳变一样会被记录。</p>
<h3>跳变的识别方法</h3>
<p>拉出登录日志里的 IP，逐条查 ASN 与城市。24 小时内 ASN 变化两次以上、城市变化一次以上，就属于跳变。家宽出口常见的地址漂移通常停留在同一 ASN、同一城市内，这种不算跳变。</p>
<h3>双 ISP 出口怎么摆</h3>
<p>主线路走运营商 A 的原生家宽，备用线路走运营商 B，两条都在同一城市。健康检查用每分钟一次的探测请求，连续 3 次超时（单次超时 5 秒）才切换，避免网络抖动引起频繁切换。切换后记录时间点，交接时能对上。</p>

<h2>五、二十分钟排查顺序与止损动作</h2>
<p>顺序很重要，先做便宜的检查，再做贵的动作。</p>
<h3>前五分钟：看告警与日志</h3>
<p>导出异常账号清单、登录 IP、时间戳。三条信息齐了，段级还是号级基本能判断。这一步不需要任何工具，后台导出加一个表格就够。</p>
<h3>中间十分钟：查 ASN 与承载量</h3>
<p>批量查 ASN，用脚本循环调 ipinfo 接口，一次查 20 个不费事。再对代理面板的连接列表做一次聚合，看有没有一号多出口或一出口多号。</p>
<h3>最后五分钟：决定撤还是留</h3>
<p>段级问题的处置是整段撤，号级问题的处置是单号隔离。两种动作不要混着做，混着做会导致事后无法归因，下次再出问题还是从头查。</p>

<h2>常见问答</h2>
<h3>换了家宽出口之后，原来的号还能救回来吗？</h3>
<p>答：能不能恢复取决于异常原因。段级问题换段后有较大概率恢复正常使用，但需要给一段平稳期，不要在换完当天就高强度使用。账号本身被限制的，只能走官方申诉渠道，不要尝试别的办法。</p>
<h3>双 ISP 备份是不是必须的？</h3>
<p>答：单条线路能稳定跑满 30 天不间断的，可以先不上备份。历史上出现过单月两次以上掉线、且掉线时长超过半小时的，就值得备一条，主要价值是避免中途换区。</p>
<h3>怎么判断一条出口有没有被多人用过？</h3>
<p>答：查这条 IP 近期是否频繁出现在不同账号的登录记录里，以及供应商是否按"独享"售卖。共享池里的地址无法追溯使用历史，独享地址至少能把范围收敛到自己团队。</p>
<h3>整段撤的时候，账号要不要同时停用？</h3>
<p>答：建议短暂停用 24 至 48 小时，让新出口的环境先稳定下来。迁移当天就全量恢复使用，等于把两个变量同时压上去，出问题又得重查一遍。</p>
